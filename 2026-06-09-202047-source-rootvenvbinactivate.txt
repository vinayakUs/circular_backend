❯ explain ON CONFLICT DO UPDATE?                                                

  Thought for 5s (ctrl+o to expand)

● ON CONFLICT DO UPDATE is a PostgreSQL feature for atomic upsert — insert a
  row, or if a conflict exists on a unique constraint, update it instead.

  INSERT INTO circulars (source, circular_id, title, ...)
  VALUES ('SEBI', 'SEBI/HO/CFD/...', 'Some Title', ...)
  ON CONFLICT (source, circular_id) DO UPDATE
  SET title = EXCLUDED.title, url = EXCLUDED.url, ...;

  How it works:

  1. Try to INSERT the row
  2. If source, circular_id violates a unique constraint (record already exists)
  → instead of failing, UPDATE the existing row
  3. EXCLUDED is a virtual table referring to the values that were attempted to
  insert

  Without it — what you have now in two queries:
  # Query 1: SELECT to check existence
  cursor.execute("SELECT id FROM circulars WHERE source = %s AND circular_id = 
  %s", ...)
  existing = cursor.fetchone()

● ON CONFLICT DO UPDATE is a PostgreSQL feature for atomic upserts — it replaces
  the current SELECT-then-INSERT/UPDATE pattern in upsert_circular with a
  single query:

  Current pattern (2 queries):
  cursor.execute("SELECT id FROM circulars WHERE source = %s AND source_item_key

  else:
      cursor.execute("INSERT ...")

  With ON CONFLICT (1 query):
  cursor.execute("""
      INSERT INTO circulars (...) VALUES (...)
      ON CONFLICT (source, source_item_key) DO UPDATE SET ...
  """)

  We discussed it earlier as a future refactor to keep the repository cleaner.

  for later?

  Thought for 9s (ctrl+o to expand)

● ON CONFLICT DO UPDATE — how it works:

  INSERT INTO circulars (source, source_item_key, circular_id, title, ...)
  VALUES ('NSE', 'CML74625:Listing', 'CML74625', 'Some Title', ...)
  ON CONFLICT (source, source_item_key) DO UPDATE
  SET title = EXCLUDED.title,
      url = EXCLUDED.url,
      ...

  Flow:
  1. Try INSERT — if (source, source_item_key) doesn't exist → row is inserted ✓
  2. If conflict (row already exists) → instead of failing, UPDATE the existing
  row with the new values

  EXCLUDED is a virtual table containing the values that were attempted to
  INSERT (i.e., the new values). So EXCLUDED.title = the new title being passed
  in.

  Benefits over current approach:

  ┌────────────────────┬────────────────────────────────────┬───────────────┐
  │       Aspect       │     Current (SELECT + branch)      │  ON CONFLICT  │
  ├────────────────────┼────────────────────────────────────┼───────────────┤
  │ DB queries         │ 2 per upsert                       │ 1 per upsert  │
  ├────────────────────┼────────────────────────────────────┼───────────────┤
