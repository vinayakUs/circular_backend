● Notification Module — High-Level Black-Box Architecture

  Core Idea

  Two independent flows converge into a Notification Engine that pushes matching
  items into the user's inbox.

  ┌──────────────┐         ┌─────────────────────┐         ┌──────────────┐
  │  Source      │ ──────▶ │                     │ ──────▶ │   User       │
  │  Ingestion   │ new     │   NOTIFICATION      │ match   │   Inbox /    │
  │  (SEBI/NSE)  │ circulars│   ENGINE           │ event   │   Delivery   │
  └──────────────┘         │                     │         └──────────────┘
                           │  ┌───────────────┐  │
  ┌──────────────┐ manage  │  │ Trigger       │  │         ┌──────────────┐
  │  User UI     │ ◀──────▶│  │ Store         │  │◀──────▶ │  Email /     │
  │  (login)     │  CRUD   │  └───────────────┘  │  send   │  Push        │
  └──────────────┘         └─────────────────────┘         └──────────────┘

  Black Boxes

  1. Trigger Manager (user-facing)

  - Input: Logged-in user, trigger definitions
  - Output: Persisted trigger rules
  - Responsibilities: CRUD on user-defined triggers

  Trigger shape (logical):

  ┌─────────────┬──────────────────────────────────────────┐
  │    Field    │                 Example                  │
  ├─────────────┼──────────────────────────────────────────┤
  │ name        │ "All SEBI audit circulars"               │
  ├─────────────┼──────────────────────────────────────────┤
  │ sources     │ ["SEBI"] (or empty = all)                │
  ├─────────────┼──────────────────────────────────────────┤
  │ keywords    │ ["audit", "compliance"] (or empty = all) │
  ├─────────────┼──────────────────────────────────────────┤
  │ match_logic │ AND / OR                                 │
  ├─────────────┼──────────────────────────────────────────┤
  │ channels    │ ["inbox", "email"]                       │
  ├─────────────┼──────────────────────────────────────────┤
  │ active      │ true/false                               │
  └─────────────┴──────────────────────────────────────────┘

  2. Circular Ingestion (existing, upstream)

  - Input: Raw PDFs / feeds from SEBI, NSE, BSE, …
  - Output: Normalized Circular objects (title, body, source, date, metadata)

  3. Notification Engine (the matcher)

  - Input: New Circular + active Triggers
  - Output: Zero or more Notification events
  - Responsibilities: For each new circular, evaluate it against every active
  trigger; if matched, emit a notification.

  Matching logic (per trigger):
  if trigger.sources contains circular.source
     AND trigger.keywords ⊆ tokenize(circular.title + body)
     → match = true   (assuming AND logic)

  4. Notification Store

  - Input: Notification events
  - Output: Per-user inbox feed (read/unread, timestamp, link back to circular)
  - Responsibilities: Persist + expose read APIs

  5. Delivery Dispatcher

  - Input: Notification events + user channel preferences
  - Output: Sent via in-app / email / push

  6. User Inbox UI

  - Input: Authenticated user
  - Output: List of notifications, mark-as-read, link to full circular

  Data Flow — Two Paths

  Path A — User manages triggers (sync)
  Login → Dashboard → Notifications page
       → create/edit trigger → Trigger Manager → Trigger Store

  Path B — New circular arrives (async)
  Ingestion → Normalized Circular
            → Notification Engine
                ↳ evaluate vs Trigger Store
                ↳ emit events → Notification Store + Dispatcher

  Trigger Evaluation Strategy — Two Options

  ┌───────────────────────────────┬────────────────────┬────────────────────┐
  │            Option             │        Pros        │        Cons        │
  ├───────────────────────────────┼────────────────────┼────────────────────┤
  │ Eager — run matcher on every  │ Immediate, simple  │ Tight coupling to  │
  │ ingest                        │                    │ ingest path        │
  ├───────────────────────────────┼────────────────────┼────────────────────┤
  │ Queue-driven — circular goes  │ Decoupled,         │ Slight latency     │
  │ to queue, engine consumes     │ scalable,          │ (sub-second)       │
  │                               │ retryable          │                    │
  └───────────────────────────────┴────────────────────┴────────────────────┘

  Recommendation: Queue-driven. Match eval becomes a consumer of the same queue
  your other downstream processors use.

  Database Sketch

  users              triggers                 notifications
  ─────              ────────                 ──────────────
  id                 id  (FK user)            id   (FK user)
  email              name                     circular_id (FK)
                     sources[]                trigger_id  (FK)
                     keywords[]               read (bool)
                     logic (AND/OR)           created_at
                     channels[]               delivered_channels[]
                     active
                     created_at

  Out of Scope (for v1)

  - Frequency digesting ("don't email me more than 1×/hour")
  - ML-based relevance ranking
  - Shared team triggers
  - Per-circular "watchlist" (vs rule-based)

  5. Service Layer — Matching Engine (core)

  # notifications/services/matching_service.py
  import re
  from typing import List
  from notifications.models import NotificationTrigger

  class MatchingService:

      @staticmethod
      def normalize(text: str) -> List[str]:
          return re.findall(r"\b[a-zA-Z][a-zA-Z0-9\-]{2,}\b", (text or
  "").lower())

      @classmethod
      def evaluate(cls, circular, trigger: NotificationTrigger) -> dict | None:
          """Returns {matched_keywords: [...]} or None."""
          # ── source filter ──
          if trigger.sources and circular.source not in trigger.sources:
              return None

          # ── keyword filter ──
          if not trigger.keywords:
              return {"matched_keywords": []}        # source-only match

          haystack = set(cls.normalize(circular.title + " " + (circular.summary
  or "")))
          target   = set(k.lower() for k in trigger.keywords)

          if trigger.match_logic == "AND":
              hit = target.issubset(haystack)
          else:  # OR
              hit = bool(target & haystack)

          return {"matched_keywords": sorted(target & haystack)} if hit else
  None

      @classmethod
      def find_matching_triggers(cls, session, circular) ->
  List[NotificationTrigger]:
          triggers = (session.query(NotificationTrigger)
                      .filter(NotificationTrigger.active == True).all())
          return [t for t in triggers if cls.evaluate(circular, t)]

  8. Delivery Service

  # notifications/services/delivery_service.py
  class DeliveryService:
      def __init__(self, smtp, ws_pusher=None):
          self.smtp = smtp
          self.ws = ws_pusher

      def dispatch(self, notification, trigger):
          delivered = []
          for channel in trigger.channels:
              if channel == "inbox":
                  delivered.append("inbox")           # already persisted
              elif channel == "email":
                  self._send_email(notification)
                  delivered.append("email")
              elif channel == "push" and self.ws:
                  self.ws.push(notification.user_id, notification.title)
                  delivered.append("push")
          notification.delivered_channels = delivered

  9. Matcher Worker (consumer)

  # notifications/workers/matcher_worker.py
  import json, pika, logging
  from notifications.services.matching_service import MatchingService
  from notifications.services.delivery_service import DeliveryService

  log = logging.getLogger(__name__)

  def handle_message(ch, method, body):
      circular = Circular.from_dict(json.loads(body))
      with db_session() as s:
          for trigger in MatchingService.find_matching_triggers(s, circular):
              notif = NotificationService.upsert(s, circular, trigger)
              DeliveryService().dispatch(notif, trigger)
      ch.basic_ack(method.delivery_tag)

  def run():
      conn = pika.BlockingConnection(pika.ConnectionParameters("rabbitmq"))
      ch   = conn.channel()
      ch.queue_declare(queue="circulars.ingested", durable=True)
      ch.basic_qos(prefetch_count=20)
      ch.basic_consume(queue="circulars.ingested",
  on_message_callback=handle_message)
      log.info("Matcher worker started")
      ch.start_consuming()

● LLD — Email-Only Notifications (Scheduler-Based, No Queue)

  Approach

  Replace the message-queue consumer with APScheduler running in a background
  thread inside the Flask app (or a separate worker process). The scheduler
  periodically polls for new circulars since last run and runs the matcher.

  # notifications/scheduler.py
  import logging
  from apscheduler.schedulers.background import BackgroundScheduler
  from apscheduler.triggers.interval import IntervalTrigger
  from notifications.jobs.matcher_job import run_matcher
  from config import Config

  log = logging.getLogger(__name__)

  _scheduler: BackgroundScheduler | None = None

  def start_scheduler(app):
      """Call once during app startup (create_app)."""
      global _scheduler
      if _scheduler:
          return

      scheduler = BackgroundScheduler(
          timezone="UTC",
          job_defaults={"coalesce": True, "max_instances": 1}
      )
      interval = Config.NOTIFICATION_MATCH_INTERVAL_SECONDS  # e.g. 60

      scheduler.add_job(
          func=_safe_run,
          trigger=IntervalTrigger(seconds=interval),
          id="notification_matcher",
          replace_existing=True,
          next_run_time=None,        # don't fire immediately on boot
      )
      scheduler.start()
      _scheduler = scheduler
      log.info("Notification matcher scheduled every %ss", interval)


  def _safe_run():
      try:
          run_matcher()
      except Exception:
          log.exception("matcher run failed")     # never let scheduler die


  def stop_scheduler():
      if _scheduler:
          _scheduler.shutdown(wait=False)

  # app.py  (Flask factory)
  from notifications.scheduler import start_scheduler

  def create_app():
      app = Flask(__name__)
      # ... existing init ...
      start_scheduler(app)        # ← starts the background scheduler
      return app

  Matcher Job (the heart)

  # notifications/jobs/matcher_job.py
  import logging
  from sqlalchemy import select
  from notifications.models import (
      NotificationTrigger, NotificationLog, NotificationWatermark
  )
  from notifications.services.matching_service import MatchingService
  from notifications.services.email_service import EmailService
  from extensions import db_session   # your session factory

  log = logging.getLogger(__name__)


  def run_matcher():
      """Called by APScheduler every N seconds."""
      with db_session() as s:
          wm = s.get(NotificationWatermark, 1)
          last_id = wm.last_circular_id or 0

          # ── 1. fetch new circulars (cursor by id) ──
          circulars = (s.query(Circular)
                        .filter(Circular.id > last_id)
                        .order_by(Circular.id.asc())
                        .limit(200)
                        .all())
          if not circulars:
              return

          log.info("Matcher processing %d new circulars (since id=%s)",
                   len(circulars), last_id)

          # ── 2. cache active triggers for this run ──
          triggers = (s.query(NotificationTrigger)
                       .filter(NotificationTrigger.active == True)
                       .all())
          users = {u.id: u for u in
                   s.query(User).filter(User.id.in_([t.user_id for t in
  triggers])).all()}

          sent_count = 0

          # ── 3. evaluate each circular × each trigger ──
          for circ in circulars:
              for trig in triggers:
                  user = users.get(trig.user_id)
                  if not user or not user.email:
                      continue

                  hit = MatchingService.evaluate(circ, trig)
                  if not hit:
                      continue

                  # ── 4. dedup via UNIQUE INDEX ──
                  existing = (s.query(NotificationLog)
                                .filter_by(user_id=user.id,
                                           circular_id=circ.id,
                                           trigger_id=trig.id)
                                .first())
                  if existing:
                      continue

                  log_row = NotificationLog(
                      user_id=user.id,
                      trigger_id=trig.id,
                      circular_id=circ.id,
                      to_email=user.email,
                      matched_keywords=hit["matched_keywords"],
                      status="pending",
                  )
                  s.add(log_row)
                  s.flush()    # surface unique-violation now

                  # ── 5. send email ──
                  try:
                      EmailService.render_and_send(
                          user, circ, trig, hit["matched_keywords"]
                      )
                      log_row.status = "sent"
                      sent_count += 1
                  except Exception as e:
                      log_row.status = "failed"
                      log_row.error = str(e)[:500]
                      log.exception("email failed user=%s circ=%s",
                                    user.id, circ.id)

          # ── 6. advance watermark ──
          wm.last_circular_id = circulars[-1].id
          wm.last_circular_at = circulars[-1].published_at

      log.info("Matcher done — %d emails sent", sent_count)

  ---
  Failure / Recovery Considerations

  ┌──────────────────────┬──────────────────────────────────────────────────┐
  │       Failure        │                     Handling                     │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Scheduler crashes    │ max_instances=1 + coalesce=True prevents         │
  │ mid-run              │ pile-up; on restart, watermark picks up from     │
  │                      │ last successful commit                           │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │                      │ Logged as status='failed'; not re-tried          │
  │ SMTP timeout         │ automatically (avoid spamming on bad addresses). │
  │                      │  Re-try job can be a later enhancement.          │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │                      │ DB transaction rollback → watermark unchanged →  │
  │ App redeployed       │ next tick re-evaluates same batch. The UNIQUE    │
  │ mid-run              │ index on log catches any duplicates that slip    │
  │                      │ through.                                         │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Clock skew /         │ Use id-based cursor (assumes BIGSERIAL);         │
  │ non-monotonic ids    │ otherwise fall back to published_at.             │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Trigger created      │ Add apply_to_last_n_days (optional flag) — runs  │
  │ after circulars      │ a one-shot matcher against recent circulars when │
  │ already exist        │  a trigger is created.                           │
  └──────────────────────┴──────────────────────────────────────────────────┘

● How Previously-Notified Circulars Are Skipped

  Two layers of protection — belt and suspenders.

  ---
  Layer 1 — Watermark (prevents fetching them at all)

  The scheduler only queries circulars after the last processed id:

  SELECT id, title, source, summary, published_at
  FROM circulars
  WHERE id > :watermark_id           -- ← only newer circulars
  ORDER BY id ASC
  LIMIT 200;

  The watermark advances after each successful tick:

  # After processing the batch
  wm.last_circular_id = circulars[-1].id
  # committed with the same transaction as the log inserts

  So once a circular has been processed:
  - Next tick: id > watermark ⇒ already-processed circulars are never even read
  from the DB
  - After app restart: watermark is loaded from notification_watermark table —
  picks up exactly where it left off

  ---
  Layer 2 — UNIQUE Index on notification_log (defense in depth)

  Even if watermark is wrong (manual reset, DB restore, clock issues), the DB
  itself blocks duplicates:

  CREATE UNIQUE INDEX uq_log_dedupe
      ON notification_log(user_id, circular_id, trigger_id);

  This means at most one log row per (user, circular, trigger).

  In the matcher job:

  # explicit pre-check
  existing = (s.query(NotificationLog)
                .filter_by(user_id=user.id,
                           circular_id=circ.id,
                           trigger_id=trig.id)
                .first())
  if existing:
      continue            # already notified → skip

  # OR rely on the constraint:
  try:
      s.add(NotificationLog(...))
      s.flush()           # surfaces unique violation NOW, not at commit
  except IntegrityError:
      continue

  Either path: no duplicate email, ever.

  ---
  What This Looks Like Across Runs

  Tick 1 (watermark=0)
     fetched circulars: 100, 101, 102, 103
     notified A about 100, 101, 102
     watermark → 103

  Tick 2 (watermark=103)
     fetched circulars: 104, 105
     notified A about 104, 105
     watermark → 105

  Tick 3 (watermark=105)
     fetched: 106
     ... etc

  User A's trigger fires once per matching circular — never twice.

  ---
  Edge Cases Handled

  ┌─────────────────────┬───────────────────────────────────────────────────┐
  │        Case         │                   What happens                    │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │                     │ Transaction rolls back. Watermark stays at old    │
  │ App crashes         │ value. Next tick re-fetches the batch and         │
  │ mid-tick            │ re-evaluates. The UNIQUE index blocks any         │
  │                     │ duplicate email inserts.                          │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ Watermark row       │ All circulars re-evaluated. UNIQUE index blocks   │
  │ missing / reset to  │ duplicate emails. (Could spam-load the DB but     │
  │ 0                   │ won't spam users.)                                │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ User has 5          │ One email per trigger → 3 log rows → 3 unique     │
  │ triggers, circular  │ (user, circular, trigger) tuples. ✓               │
  │ matches 3           │                                                   │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ Same trigger, same  │ Second insert blocked by UNIQUE. ✓                │
  │ circular, run twice │                                                   │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ Trigger deactivated │ Re-activation does NOT re-notify for old          │
  │  then re-activated  │ circulars — UNIQUE index blocks. Only future      │
  │                     │ circulars match. ✓                                │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ New trigger created │ UNIQUE doesn't apply yet (no log row exists for   │
  │  for old circulars  │ this trigger). To handle this, see "Backfill"     │
  │                     │ below.                                            │
  └─────────────────────┴───────────────────────────────────────────────────┘

  ▎ Watermark = "don't even read old circulars"
  ▎ UNIQUE(user, circular, trigger) = "the DB refuses duplicate emails"

● Adjusting for UUID Primary Keys

  UUIDs aren't monotonic, so the id > watermark cursor won't work. Here's the
  fix.

  ---
  The Core Change

  Drop the watermark table. Use a time window + log dedup instead:

  Fetch circulars:    created_at >= NOW() - WINDOW
  Skip already-logged ones via UNIQUE index (same as before)

  Two simple queries + the same UNIQUE protection = no duplicates.

  Updated Matcher Job

  # notifications/jobs/matcher_job.py
  import logging
  from datetime import datetime, timedelta, timezone
  from sqlalchemy import select, exists, and_
  from config import Config

  log = logging.getLogger(__name__)


  def run_matcher():
      """Called by APScheduler every N seconds."""
      lookback_minutes = Config.NOTIFICATION_MATCH_LOOKBACK_MINUTES  # e.g. 30
      batch_size       = Config.NOTIFICATION_BATCH_SIZE              # e.g. 200
      cutoff           = datetime.now(timezone.utc) -
  timedelta(minutes=lookback_minutes)

      with db_session() as s:
          # ── 1. candidate circulars: recent + not yet fully processed ──
          # We rely on the UNIQUE log index for dedup, so we just need
          # a wide enough window to catch any stragglers.
          circulars = (s.query(Circular)
                        .filter(Circular.created_at >= cutoff)
                        .order_by(Circular.created_at.asc(), Circular.id.asc())
                        .limit(batch_size)
                        .all())

          if not circulars:
              return

          # ── 2. bulk-fetch existing log rows for these circulars (1 query) ──
          circ_ids = [c.id for c in circulars]
          already_logged = set(
              row.circular_id for row in
              s.query(NotificationLog.circular_id)
               .filter(NotificationLog.circular_id.in_(circ_ids))
               .all()
          )

          # ── 3. load active triggers + users ──
          triggers = (s.query(NotificationTrigger)
                       .filter(NotificationTrigger.active == True)
                       .all())
          if not triggers:
              return
          users = {u.id: u for u in
                   s.query(User).filter(User.id.in_([t.user_id for t in
  triggers])).all()}

          sent_count = 0

          # ── 4. evaluate each circular × each trigger ──
          for circ in circulars:
              for trig in triggers:
                  # short-circuit: if every (user, trig) combo already logged 
  for this circ → skip
                  if _already_logged_for(s, user_id=trig.user_id,
                                         circular_id=circ.id,
  trigger_id=trig.id):
                      continue

                  user = users.get(trig.user_id)
                  if not user or not user.email:
                      continue

                  hit = MatchingService.evaluate(circ, trig)
                  if not hit:
                      continue

                  log_row = NotificationLog(
                      user_id=trig.user_id,
                      trigger_id=trig.id,
                      circular_id=circ.id,
                      to_email=user.email,
                      matched_keywords=hit["matched_keywords"],
                      status="pending",
                  )
                  s.add(log_row)
                  try:
                      s.flush()             # surface unique violation now
                  except IntegrityError:
                      s.rollback()          # another worker beat us
                      continue

                  try:
                      EmailService.render_and_send(user, circ, trig,
  hit["matched_keywords"])
                      log_row.status = "sent"
                      sent_count += 1
                  except Exception as e:
                      log_row.status = "failed"
                      log_row.error = str(e)[:500]
                      log.exception("email failed")

      log.info("Matcher done — %d candidates, %d sent",
               len(circulars), sent_count)


  def _already_logged_for(s, *, user_id, circular_id, trigger_id) -> bool:
      return s.query(
          exists().where(and_(
              NotificationLog.user_id == user_id,
              NotificationLog.circular_id == circular_id,
              NotificationLog.trigger_id == trigger_id,
          ))
      ).scalar()

  7. Matching Engine

  # notifications/services/matching_service.py
  import re

  class MatchingService:

      _WORD_RE = re.compile(r"\b[a-zA-Z][a-zA-Z0-9\-]{2,}\b")

      @classmethod
      def normalize(cls, text: str) -> set[str]:
          return set(m.group(0).lower()
                     for m in cls._WORD_RE.finditer(text or ""))

      @classmethod
      def evaluate(cls, circular, trigger) -> dict | None:
          # ── source filter ──
          if trigger.sources and circular.source not in trigger.sources:
              return None

          # ── keyword filter ──
          if not trigger.keywords:
              return {"matched_keywords": []}      # source-only match

          haystack = cls.normalize(circular.title + " " + (circular.summary or
  ""))
          target   = {k.lower() for k in trigger.keywords}

          if trigger.match_logic == "AND":
              hit = target.issubset(haystack)
          else:                                     # OR
              hit = bool(target & haystack)

          return {"matched_keywords": sorted(target & haystack)} if hit else
  None

  import logging
  from apscheduler.schedulers.background import BackgroundScheduler
  from apscheduler.triggers.interval import IntervalTrigger

  from config import Config

  log = logging.getLogger(__name__)
  _scheduler: BackgroundScheduler | None = None


  def start_scheduler(app):
      """Call once during Flask app startup."""
      global _scheduler
      if _scheduler:
          return

      scheduler = BackgroundScheduler(
          timezone="UTC",
          job_defaults={"coalesce": True, "max_instances": 1,
  "misfire_grace_time": 300},
      )

      interval = Config.NOTIFICATION_MATCH_INTERVAL_SECONDS

      scheduler.add_job(
          func=_safe_run,
          trigger=IntervalTrigger(seconds=interval),
          id="notification_matcher",
          replace_existing=True,
          next_run_time=None,         # do not fire immediately on boot
      )
      scheduler.start()
      _scheduler = scheduler
      log.info("Notification matcher scheduled every %ss", interval)


  def _safe_run():
      try:
          run_matcher()
      except Exception:
          log.exception("matcher run failed")    # scheduler must not die


  def shutdown_scheduler():
      if _scheduler:
          _scheduler.shutdown(wait=False)

  # app.py
  from notifications.scheduler import start_scheduler

  def create_app():
      app = Flask(__name__)
      # ... your existing init (db, mail, jwt, blueprints) ...
      from notifications.services.email_service import init_mail
      init_mail(app)

      from notifications.routes import bp as notif_bp
      app.register_blueprint(notif_bp)

  10. Matcher Job (heart of the system)

  # notifications/jobs/matcher_job.py
  import logging
  from datetime import datetime, timedelta, timezone
  from sqlalchemy import select, exists, and_
  from sqlalchemy.exc import IntegrityError
  from notifications.models import NotificationTrigger, NotificationLog
  from notifications.services.matching_service import MatchingService
  from notifications.services.email_service import EmailService
  from config import Config

  log = logging.getLogger(__name__)


  def run_matcher():
      """
      Periodic job — runs every NOTIFICATION_MATCH_INTERVAL_SECONDS.
      1. Fetch circulars in the lookback window
      2. Bulk-load active triggers
      3. For each (circular, trigger): evaluate, dedup, send
      """
      lookback   = timedelta(minutes=Config.NOTIFICATION_MATCH_LOOKBACK_MINUTES)
      batch_size = Config.NOTIFICATION_BATCH_SIZE
      cutoff     = datetime.now(timezone.utc) - lookback

      with db_session() as s:
          # ── 1. candidate circulars ──
          circulars = (s.query(Circular)
                        .filter(Circular.created_at >= cutoff)
                        .order_by(Circular.created_at.asc(), Circular.id.asc())
                        .limit(batch_size)
                        .all())
          if not circulars:
              return

          # ── 2. bulk-load triggers + users (1 + 1 query) ──
          triggers = (s.query(NotificationTrigger)
                       .filter(NotificationTrigger.active == True)
                       .all())
          if not triggers:
              return
          users = {u.id: u for u in
                   s.query(User)
                    .filter(User.id.in_({t.user_id for t in triggers}))
                    .all()}

          # ── 3. bulk-load existing log rows for these circulars ──
          circ_ids = [c.id for c in circulars]
          existing = s.query(
              NotificationLog.user_id,
              NotificationLog.circular_id,
              NotificationLog.trigger_id,
          ).filter(NotificationLog.circular_id.in_(circ_ids)).all()
          logged = {(u, c, t) for (u, c, t) in existing}

          sent_count = 0

          # ── 4. evaluate ──
          for circ in circulars:
              for trig in triggers:
                  if (trig.user_id, circ.id, trig.id) in logged:
                      continue                        # already notified

                  user = users.get(trig.user_id)
                  if not user or not user.email:
                      continue

                  hit = MatchingService.evaluate(circ, trig)
                  if not hit:
                      continue

                  log_row = NotificationLog(
                      user_id=trig.user_id,
                      trigger_id=trig.id,
                      circular_id=circ.id,
                      to_email=user.email,
                      matched_keywords=hit["matched_keywords"],
                      status="pending",
                  )
                  s.add(log_row)
                  try:
                      s.flush()
                  except IntegrityError:
                      s.rollback()
                      continue                        # race with another worker

                  # ── 5. send ──
                  try:
                      EmailService.render_and_send(
                          user, circ, trig, hit["matched_keywords"]
                      )
                      log_row.status = "sent"
                      sent_count += 1
                  except Exception as e:
                      log_row.status = "failed"
                      log_row.error = str(e)[:500]
                      log.exception("email failed user=%s circ=%s",
                                    user.id, circ.id)

      log.info("Matcher done — %d candidates, %d emails sent",
               len(circulars), sent_count)

  ┌─────────────┬────────────────────────────┬──────────────────────────────┐
  │    Layer    │         Mechanism          │       What it prevents       │
  ├─────────────┼────────────────────────────┼──────────────────────────────┤
  │ Time window │ created_at >= NOW() -      │ Old circulars aren't even    │
  │             │ INTERVAL '30 min'          │ fetched                      │
  ├─────────────┼────────────────────────────┼──────────────────────────────┤
  │ In-memory   │                            │ Skip (user, circ, trig)      │
  │ set         │ logged = {...} pre-loaded  │ already in log, before any   │
  │             │                            │ DB write                     │
  ├─────────────┼────────────────────────────┼──────────────────────────────┤
  │ DB UNIQUE   │ uq_log_dedupe (user_id,    │ DB refuses duplicate inserts │
  │ index       │ circular_id, trigger_id)   │  even under race             │
  ├─────────────┼────────────────────────────┼──────────────────────────────┤
  │ s.flush()   │ Surface constraint         │ Fail fast, don't waste SMTP  │
  │             │ violation early            │ attempt                      │
  └─────────────┴────────────────────────────┴──────────────────────────────┘

  ▎ All four layers compose. The user cannot get a duplicate email.

  12. Backfill on Trigger Create

  Optional apply_to_last_n_days flag — runs the same matcher for one circular
  against the new trigger:

  # notifications/services/trigger_service.py
  def create(user_id, payload, apply_to_last_n_days: int = 0):
      trigger = NotificationTrigger(user_id=user_id, **payload)
      s.add(trigger); s.commit()

      if apply_to_last_n_days > 0:
          run_matcher_for_trigger(trigger, apply_to_last_n_days)

      return trigger


  def run_matcher_for_trigger(trigger, since_days: int):
      cutoff = datetime.now(timezone.utc) - timedelta(days=since_days)
      with db_session() as s:
          circulars = (s.query(Circular)
                        .filter(Circular.created_at >= cutoff)
                        .order_by(Circular.created_at.asc())
                        .limit(500)
                        .all())
          user = s.get(User, trigger.user_id)

          for circ in circulars:
              hit = MatchingService.evaluate(circ, trigger)
              if not hit:
                  continue
              try:
                  s.add(NotificationLog(
                      user_id=user.id, trigger_id=trigger.id,
                      circular_id=circ.id, to_email=user.email,
                      matched_keywords=hit["matched_keywords"],
                      status="pending",
                  ))
                  s.flush()
                  EmailService.render_and_send(user, circ, trigger,
  hit["matched_keywords"])
                  s.query(NotificationLog).filter_by(
                      user_id=user.id, circular_id=circ.id,
  trigger_id=trigger.id
                  ).update({"status": "sent"})
              except IntegrityError:
                  s.rollback()

  4. Database Schema — notifications/schema.sql

  Two tables. Run once with psql.

  CREATE TABLE IF NOT EXISTS notification_triggers (
      id              BIGSERIAL    PRIMARY KEY,
      user_id         BIGINT       NOT NULL REFERENCES users(id) ON DELETE
  CASCADE,
      name            VARCHAR(200) NOT NULL,
      sources         TEXT[]       NOT NULL DEFAULT '{}',
      keywords        TEXT[]       NOT NULL DEFAULT '{}',
      match_logic     VARCHAR(3)   NOT NULL DEFAULT 'AND'
                      CHECK (match_logic IN ('AND','OR')),
      active          BOOLEAN      NOT NULL DEFAULT TRUE,
      created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
      updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
  );
  CREATE INDEX IF NOT EXISTS idx_triggers_active ON notification_triggers
  (active);
  CREATE INDEX IF NOT EXISTS idx_triggers_user   ON notification_triggers
  (user_id, created_at DESC);

  CREATE TABLE IF NOT EXISTS notification_log (
      id                BIGSERIAL    PRIMARY KEY,
      user_id           BIGINT       NOT NULL REFERENCES users(id) ON DELETE
  CASCADE,
      trigger_id        BIGINT       REFERENCES notification_triggers(id) ON
  DELETE SET NULL,
      circular_id       UUID         NOT NULL REFERENCES circulars(id) ON DELETE
  CASCADE,
      to_email          VARCHAR(255) NOT NULL,
      matched_keywords  TEXT[]       NOT NULL DEFAULT '{}',
      status            VARCHAR(20)  NOT NULL
                        CHECK (status IN
  ('sent','failed','skipped_dup','pending')),
      error             TEXT,
      sent_at           TIMESTAMPTZ  NOT NULL DEFAULT NOW()
  );
  CREATE UNIQUE INDEX IF NOT EXISTS uq_log_dedupe
      ON notification_log (user_id, circular_id, trigger_id);
  CREATE INDEX IF NOT EXISTS idx_log_circular  ON notification_log
  (circular_id);
  CREATE INDEX IF NOT EXISTS idx_log_user_time ON notification_log (user_id,
  sent_at DESC);

  The UNIQUE index on (user_id, circular_id, trigger_id) is the dedup guarantee.
  It means: at most one log row per email attempt — the DB refuses duplicates
  even under race conditions.

  9. Matcher Job — notifications/jobs/matcher_job.py

  Runs every N seconds via APScheduler. Pseudocode:

  run_matcher():
      cutoff = NOW() - lookback_minutes
      with get_conn() as c:
          circulars  = find_recent_circulars(c, cutoff, batch_size)
          triggers   = load_active_triggers(c)
          users      = load_users(c, [t.user_id for t in triggers])
          logged     = find_logged_combos(c, [circ.id for circ in circulars])

          for circ in circulars:
              for trig in triggers:
                  if (trig.user_id, circ.id, trig.id) in logged: continue
                  user = users.get(trig.user_id); if not user: continue

                  hit = MatchingService.evaluate(circ, trig)
                  if not hit: continue

                  log = NotificationLog(status="pending", ...)
                  try:
                      insert_log(c, log)        # UNIQUE blocks dupes
                      EmailService.render_and_send(...)
                      update_log_status(c, log.id, "sent")
                  except IntegrityError: continue
                  except Exception as e:
                      update_log_status(c, log.id, "failed", str(e))

  Validators — clean data on the way IN

  @field_validator("keywords")
  @classmethod
  def _clean_keywords(cls, v: list[str]) -> list[str]:
      cleaned = [k.strip().lower() for k in v if k and k.strip()]
      if any(len(k) < 3 for k in cleaned):
          raise ValueError("each keyword must be at least 3 characters")
      return cleaned

  What this does:
  1. Strips whitespace
  2. Lowercases everything (so "Audit" and "audit" are the same)
  3. Drops empty strings
  4. Rejects keywords shorter than 3 characters (avoids noisy matches like "AI",
  "OF")
  5. Returns the cleaned list

  @field_validator("sources")
  @classmethod
  def _clean_sources(cls, v: list[str]) -> list[str]:
      return [s.strip().upper() for s in v if s and s.strip()]

  Same idea but uppercase — sources in your codebase are uppercase codes
  ("SEBI", "NSE").

  2. TriggerCreate — what the POST body looks like

  class TriggerCreate(TriggerBase):
      apply_to_last_n_days: int = Field(default=0, ge=0, le=90)

  Inherits all TriggerBase fields. Adds one extra:
  - apply_to_last_n_days — optional backfill knob (0–90)

  Why? When a user creates a new trigger, it only fires on future circulars.
  Without backfill, the trigger looks broken until new circulars arrive. This
  flag says: "also evaluate against circulars from the last N days so I can see 
  it working immediately."

  Example valid request body:

  {
    "name": "SEBI audit alerts",
    "sources": ["SEBI"],
    "keywords": ["audit", "regulatory"],
    "match_logic": "AND",
    "active": true,
    "apply_to_last_n_days": 7
  }

  Example 422 response (invalid):

  {
    "detail": [
      { "loc": ["body", "keywords"], "msg": "each keyword must be at least 3 
  characters" }
    ]
  }

  4. Database Schema — notifications/schema.sql

  CREATE TABLE IF NOT EXISTS notification_triggers (
      id              BIGSERIAL    PRIMARY KEY,
      user_id         BIGINT       NOT NULL REFERENCES users(id) ON DELETE
  CASCADE,
      name            VARCHAR(200) NOT NULL,
      sources         TEXT[]       NOT NULL DEFAULT '{}',
      keywords        TEXT[]       NOT NULL DEFAULT '{}',
      match_logic     VARCHAR(3)   NOT NULL DEFAULT 'AND'
                      CHECK (match_logic IN ('AND','OR')),
      active          BOOLEAN      NOT NULL DEFAULT TRUE,
      created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
      updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
  );
  CREATE INDEX IF NOT EXISTS idx_triggers_active ON notification_triggers
  (active);
  CREATE INDEX IF NOT EXISTS idx_triggers_user   ON notification_triggers
  (user_id, created_at DESC);

  CREATE TABLE IF NOT EXISTS notification_log (
      id                BIGSERIAL    PRIMARY KEY,
      user_id           BIGINT       NOT NULL REFERENCES users(id) ON DELETE
  CASCADE,
      trigger_id        BIGINT       REFERENCES notification_triggers(id) ON
  DELETE SET NULL,
      circular_id       UUID         NOT NULL REFERENCES circulars(id) ON DELETE
  CASCADE,
      to_email          VARCHAR(255) NOT NULL,
      matched_keywords  TEXT[]       NOT NULL DEFAULT '{}',
      status            VARCHAR(20)  NOT NULL
                        CHECK (status IN
  ('sent','failed','skipped_dup','pending')),
      error             TEXT,
      sent_at           TIMESTAMPTZ  NOT NULL DEFAULT NOW()
  );
  CREATE UNIQUE INDEX IF NOT EXISTS uq_log_dedupe
      ON notification_log (user_id, circular_id, trigger_id);
  CREATE INDEX IF NOT EXISTS idx_log_circular  ON notification_log
  (circular_id);
  CREATE INDEX IF NOT EXISTS idx_log_user_time ON notification_log (user_id,
  sent_at DESC);

  Key invariant: UNIQUE(user_id, circular_id, trigger_id) = at most one email
  per (user, circular, trigger). The DB enforces this; the matcher relies on it.

  9. Matcher Job — notifications/jobs/matcher_job.py

  Runs every N seconds via APScheduler.

  def run_matcher():
      cutoff = NOW() - lookback_minutes
      with get_conn() as c:
          circulars = find_recent_circulars(c, cutoff, batch_size)
          triggers  = load_active_triggers(c)
          if not triggers: return
          users     = load_users(c, [t.user_id for t in triggers])
          logged    = find_logged_combos(c, [c.id for circ in circulars])

          for circ in circulars:
              for trig in triggers:
                  if (trig.user_id, circ.id, trig.id) in logged: continue
                  user = users.get(trig.user_id)
                  if not user or not user.email: continue

                  hit = MatchingService.evaluate(circ, trig)
                  if not hit: continue

                  log = NotificationLog(status="pending", ...)
                  try:
                      insert_log(c, log)                    # UNIQUE blocks 
  dupes
                      EmailService.render_and_send(...)
                      update_log_status(c, log.id, "sent")
                  except IntegrityError: continue
                  except Exception as e:
                      update_log_status(c, log.id, "failed", str(e))

  12. Deduplication — How It Works

  ┌────────────────────────────┬────────────────────────────────────────────┐
  │           Layer            │                What it does                │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ Time window (created_at >= │ Old circulars not even fetched             │
  │  NOW() - 30min)            │                                            │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ In-memory logged set       │ Pre-loaded before the loop; skip           │
  │                            │ already-logged combos without writing      │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ DB UNIQUE(user, circular,  │ DB refuses duplicate inserts even under    │
  │ trigger) index             │ race                                       │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ flush() after insert       │ Surfaces constraint violation early, no    │
  │                            │ wasted SMTP call                           │
  └────────────────────────────┴────────────────────────────────────────────┘

  13. Failure Modes

  ┌─────────────────────────┬───────────────────────────────────────────────┐
  │         Failure         │                   Handling                    │
  ├─────────────────────────┼───────────────────────────────────────────────┤
  │ App crash mid-tick      │ Transaction rolls back; next tick             │
  │                         │ re-evaluates; UNIQUE blocks dupes             │
  ├─────────────────────────┼───────────────────────────────────────────────┤
  │ SMTP outage             │ Caught per-email; logged as failed; no        │
  │                         │ auto-retry                                    │
  ├─────────────────────────┼───────────────────────────────────────────────┤
  │ Trigger created after   │ No email — and never will be for those past   │
  │ circulars exist         │ circulars                                     │
  ├─────────────────────────┼───────────────────────────────────────────────┤
  │ Trigger deactivated     │ Won't re-notify for past circulars (UNIQUE    │
  │ then re-activated       │ blocks). Only future circulars match.         │
  ├─────────────────────────┼───────────────────────────────────────────────┤
  │ Multi-process deploy    │ UNIQUE keeps it safe; scheduler should run on │
  │                         │  one process only (or wrap with a DB lock)    │
  └─────────────────────────┴───────────────────────────────────────────────┘

  15. End-to-End Flow

  Flow A — User manages triggers

  Login → /notifications/triggers
       → POST /api/notifications/triggers   (TriggerCreate)
       → TriggerService.create()
       → repository.create_trigger()
       → 201 + TriggerOut

  Flow B — New circular arrives, emails get sent

  Scraper → INSERT INTO circulars
          → (60s later) Scheduler tick
          → MatcherJob.run_matcher()
              ├─ SELECT recent circulars (time window)
              ├─ SELECT active triggers
              ├─ SELECT existing log combos
              └─ for each (circ, trig):
                   ├─ skip if in logged set
                   ├─ MatchingService.evaluate()
                   ├─ INSERT log row (UNIQUE blocks dupes)
                   ├─ SMTP send
                   └─ UPDATE log status
